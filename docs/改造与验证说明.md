# 改造与验证说明

版本日期：2026-11-07。

## macOS 改造

- 新增可双击的应用与安装、启动、停止、状态入口，应用启动器为 Intel / Apple Silicon 双架构。
- 使用 macOS Python 虚拟环境和 Bleak CoreBluetooth 后端，替代 Windows Python、PowerShell 和 CMD 入口。
- 原生 Swift / AppKit 应用在后台启动服务；另保留终端前台 `.command` 入口。可选登录自启通过 launchd 启动后台服务。
- 默认端口 18299，监听 127.0.0.1；修复原服务忽略 server.host 的问题。
- 使用 runtime/config.yaml、runtime/port_history.db 和 runtime/*.log；配置初次创建为空，权限为 600。
- 启动使用文件锁避免重复实例；停止仅针对本目录持锁的监管进程，并等待子进程退出。
- 启动时清除继承的设备 / MQTT / 巴法云配置环境变量，避免旧 shell 环境覆盖本目录的空白配置。
- 原 cuktech_ctl.sh 在 Mac 上转到新入口；环境检查识别根目录虚拟环境。
- ESP32 Web 重建脚本改用 macOS 可用的文件大小命令，烧录脚本增加 Mac USB 串口匹配。

## 全新数据与称呼

- 已删除原下载目录中的设备配置、配置备份、数据库及 WAL/SHM、日志和临时数据填充脚本，源码中不含任何真实设备凭据。
- 检查原 zip 目录清单，未发现同名配置、日志和数据库副本。macOS 版本中不含原 zip 或 Windows Python。
- 网页、服务消息、中文语言包、说明及测试中的指定称呼已统一为“米家”；检查 gzip 内容无遗留。
- 英文界面相应显示 Mi Home；保留 xiaomi API 路径、模块名、协议和域名，以保持服务兼容。
- 应用名称为中文“酷态站”、英文“CUKTECH Station”，保留原项目许可、来源及设备产品型号。

## 审阅中修复

原服务的内部清理入口误用了跳过活跃会话的批量删除规则，导致崩溃遗留的 0Wh 记录及其采样点清理失败。已允许内部清理删除待丢弃的未闭合记录，同时保留网页批量删除对活跃会话的保护，并补充回归测试。

修正原有测试中缺少实际功率的模拟端口，补齐 JS 沙箱的 Image 对象，更新页面标题断言。以上为测试环境适配，不改变充电协议。

## 本轮核查与修复

- 删除主设备时按原设备来源继承凭据，避免把被删设备的 token / BLE Key 给下一台；支持删除到空配置后重新添加。
- 重命名、清空名称、修改设备标识时保留原设备凭据；修复附加设备空 BLE Key 输入导致原值丢失的问题。
- 切换账号后忽略尚未完成的旧登录、轮询和导入响应；服务端退出后不再返回旧账号设备，也不再自动保存旧账号导入结果。
- 米家客户端退出时清除账号与认证缓存；失败的二维码请求会释放客户端，晚到的扫码响应不能恢复已关闭账号。
- 浏览器批量导入统一等完整配置保存后重启，避免只保存首台就提前重启。
- 配置及导入写入的临时文件权限为 600，替换后仍保持私有权限。
- 对外页面、双语标题、启动器、应用标识、说明统一为通用名称；可选 Linux 示例使用通用服务用户和安装目录。
- 清理本机运行配置、数据库、日志、旧应用与缓存；说明截图全部重新生成，使用空配置，不含真实设备或账号。

## 蓝牙连接失败反馈（2026-11-06）

桌面主页和手机页在连接区域持续显示失败原因及处理建议，覆盖自动连接、手动连接和断线重连。扫描、建立连接与认证合计最多等待 60 秒；超时原因即时发布，成功或主动停止后清除。失败期间可立即重试或停止，自动重试和设备内部重建保留最近错误。占用无法确定时只作为可能原因展示。

诊断状态通过每设备 HTTP 快照和 SSE 同步，刷新、设备切换及旧请求返回不会串台。状态推送会即时唤醒浏览器，并保持每设备只发送最新状态；MQTT 原有载荷保持兼容。蓝牙扫描错误不再被统一吞成“未找到”，取消某台设备的等待不会中断其他设备的共享扫描。

本轮验证：Python 服务及 macOS 测试共 908 项通过，包含 32 项连接反馈专项回归；13 个 JavaScript 测试脚本通过。Playwright 在 1280×900 桌面页和 390×844 手机页验证失败、刷新、重试、停止、超时、成功清除、多设备隔离、中文/英文、浅色/深色与本地服务不可达。正常流程没有新增页面或控制台错误；模拟断网时出现预期通信错误提示。截图检查确认提示不遮挡标题或按钮，无横向溢出。

上述蓝牙失败场景使用隔离的演示替身，不使用真实账号或充电器；手机占用时真实 macOS 返回的具体原因仍需真机测试。实际本地服务已重启，健康检查、新页面脚本及诊断接口验证通过。
